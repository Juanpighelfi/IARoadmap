# Evaluación técnica — opcional

Sirve para probar un sistema, no para calificarte como estudiante. Usala cuando una función ya tenga entradas y resultados esperados; no para cada sesión de estudio.

## Qué pruebo

Función, versión y entorno de prueba. Ejemplo: decidir si un turno cabe en una franja, con datos ficticios.

## Casos

Antes de ejecutar, escribí qué debería pasar. Después completá el resultado real.

| Entrada o situación | Qué espero | Qué ocurrió |
| --- | --- | --- |
| | | |

Ejemplo de caso: turno que termina después del cierre → debe rechazarse. Agregá un caso válido, uno inválido y uno límite; los casos adicionales dependen de la función. Si no lo ejecutaste, escribí «sin probar».

## Conclusión

Qué funciona, qué falla y qué no probaste. Incluí el enlace o comando de las pruebas. Los controles de permisos, seguridad, costo o latencia que exija el proyecto siguen siendo necesarios.

Si ya tenés tests o un informe con esta información, enlazalos; no copies todo a otra tabla. Para tu estudio, anotá solo el bloqueo o siguiente paso en [Mi seguimiento](../00-MOC/Estado%20actual.md).
